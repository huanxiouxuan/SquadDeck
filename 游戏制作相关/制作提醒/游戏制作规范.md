# 游戏制作规范（开黑启动器）

> 目标：任何人（或 AI）照这份规范做的游戏，都能**导入启动器直接玩**——
> 不改内核、不重编 jar、不重启服务器。
>
> 适用版本：世界插件化之后（内核里已经**没有任何一个具体游戏**）。

---

## 〇、一句话原则

**一个游戏 = `gamemode/<id>/` 一个文件夹**：`game.json` + 网页文件；
要联机就再加 `server/` 里的服务端类。

内核只提供三样东西：静态文件路由（`/games/<id>/`）、通用接口
（`/api/<id>/{join,sync,leave,info}`）、世界加载与启停。
（启动器自用的聊天 `/api/chat` 与游戏无关，游戏不用管。）

---

## 一、最小可用

### 纯单机（3 个文件，零服务端）

```
mygame/
├── game.json
├── index.html
└── game.js
```

```json
{
  "id": "mygame",
  "name": "我的游戏",
  "desc": "一句话简介",
  "icon": "🎮",
  "entry": "index.html",
  "version": 1
}
```

> 单机游戏**不要**写 `world` —— 写了启动器会给它一个启停开关，但没人会去拨。

### 联机（多一个服务端类）

```
mygame/
├── game.json          ← 多一行 "world": "lkserver.MyWorld"
├── index.html
├── game.js
└── server/
    └── MyWorld.java   ← 实现 GameWorldPlugin
```

---

## 二、game.json 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 目录名 / URL 片段，只能 `[a-z0-9_-]`，≤32 字符 |
| `name` | ✅ | 显示名，≤12 字符 |
| `desc` | | 简介，≤60 字符 |
| `icon` | | emoji，或游戏目录里的图片文件名（如 `tank.ico`）；缺省 🎮 |
| `entry` | | 入口页，缺省 `index.html` |
| `api` | | 接口前缀，缺省 `/api/<id>`（**只是展示用**，真实路由按 id 走） |
| `world` | 联机必填 | 服务端类全限定名，如 `lkserver.MyWorld` |
| `autostart` | | `true` = 随服务器自启；缺省 = 等房主在启动器里拨开关 |
| `version` | | 随便 |

⚠️ `world` 写错（类名/包名不对）→ 拨开关时加载失败，接口永远 409。

## 三、客户端三件事

### 3.1 取游戏 id：**绝对不要写死**

游戏被「添加游戏」导入后，id 由服务端重新生成（`g` + base36 时间戳），
**不是** game.json 里那个。

```js
var GID = (location.pathname.match(/\/games\/([^\/]+)/) || [])[1] || 'mygame';
var API = '/api/' + GID;
```

> 写死 `/api/mygame` 的游戏，直接放进 gamemode 能跑，
> 一旦被导入就全 404 —— 这是最容易犯的错。

### 3.2 三个接口

| 接口 | 参数（form-urlencoded） | 返回 |
|---|---|---|
| `POST {API}/join` | `name`, `cid` | `{id, ...}`：玩家 id + 世界参数 |
| `POST {API}/sync` | `id` + 你自定义的输入 | 世界快照（结构你自己定） |
| `POST {API}/leave` | `id` | `{ok:true}` |

统一 post 助手：

```js
function post(path, params) {
  return fetch(path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams(params).toString(),
    cache: 'no-store'
  }).then(function (r) { return r.json(); });
}
```

**sync 的设计要点**：一次往返同时「上报输入」+「拿回状态」，
别拆成两个请求（请求数翻倍，输入和状态还对不上）。

**错误码**：
- **409** = 游戏世界没启动（房主还没拨开关）→ 提示"等房主开启"，可自动重试
- **404** = 游戏不存在

### 3.3 身份（cid）

浏览器 `sessionStorage` 存一个随机 cid，join 时带上。服务端据此在刷新 /
断线重连时**复用原角色**，不会凭空多出一个号。

```js
function getCid() {
  var c = sessionStorage.getItem('mygameCid');
  if (!c) {
    c = 'c' + Math.random().toString(36).slice(2, 10) + Date.now().toString(36);
    sessionStorage.setItem('mygameCid', c);
  }
  return c;
}
```

### 3.4 与启动器联动：只接「名字登记」

启动器只通过 `postMessage` 下发**名字**：

```js
window.addEventListener('message', function (ev) {
  var d = ev.data;
  if (d && d.kaihei === 'name') { myName = d.n.slice(0, 10); }
});
```

接了就省掉自己填名字的输入框；不接也能玩。

> **表情栏和聊天框是启动器自己的功能，不属于任何游戏** —— 它们全服共享、
> 与游戏之间零协议。游戏**不要**自己实现表情/聊天，也不要读取或渲染它们的内容。
> （启动器的聊天走内核的 `/api/chat`，游戏完全不用管。）

### 3.5 渲染要点

- **别每帧用 `shadowBlur`** —— 软渲染 / 集显上很贵，是"一卡一卡"的常见元凶。
  预渲染到离屏 canvas，之后只 `drawImage`。
- 逻辑用**固定 tick + 累加器**，画面用 `requestAnimationFrame` 在 tick 之间插值，
  低速档也不会一顿一顿。
- 圆角矩形用**标准四段 `arcTo`**（见"已知坑"第一条）。

## 四、服务端四件事

### 4.1 实现 `GameWorldPlugin`

```java
package lkserver;   // 必须在这个包，否则用不了内核的工具类

public final class MyWorld implements GameWorldPlugin {

    @Override public void start() { /* 起 tick 线程 */ }
    @Override public void stop()  { /* 关 tick 线程 */ }

    @Override
    public String join(String rawName, String rawCid) {
        return "{\"id\":\"p1\"}";          // 必须含 id
    }

    @Override
    public String sync(String id, java.util.Map<String, String> p) {
        int x = GameWorldPlugin.intOf(p, "x", 0);   // 注意带类名
        return "{\"t\":0}";
    }

    @Override public void leave(String id) { }
    @Override public String info() { return "{\"players\":0}"; }
    @Override public int playerCount() { return 0; }
}
```

### 4.2 方法语义

| 方法 | 约定 |
|---|---|
| `start` / `stop` | 起 / 停 tick。**`stop` 只停线程、不清数据**；再 `start` 等同重开一局 |
| `join(name, cid)` | 返回**完整 JSON**（必须含 `id`）；同 cid 复用旧角色 |
| `sync(id, params)` | 一回合：读输入 + 返回快照；返回 `null` → 客户端拿到 500 |
| `leave(id)` | 主动退出 |
| `info()` | 返回完整 JSON（在线人数 / 尺寸等） |
| `playerCount()` | **在线**人数（离线未超时的 ghost 不算）——启停和删除会用它判断"有没有人在玩" |

### 4.3 线程安全

tick 线程 + HTTP 线程会同时碰世界状态 → **所有对外方法加 `synchronized`**，
临界区别写太长（这个规模足够）。

### 4.4 能直接用的内核工具

| 类 / 方法 | 用途 |
|---|---|
| `Json.quote(s)` | 字符串转义成 JSON |
| `Json.str(map, key, def)`、`Json.parse` | 读 JSON / 解析 JSON 文本 |
| `GameWorldPlugin.intOf / longOf / doubleOf / boolOf` | 从参数表取值，**带容错**（垃圾输入不崩） |

> 不要自己复制一份到游戏目录——这些是内核类，插件通过父类加载器直接用。

### 4.5 编译与加载（关键机制）

世界类**放在游戏目录里**，内核启动世界时按优先级加载：

1. `server.jar` —— 编译好的插件包；
2. `server/**/*.java` —— **源码，内核用 JDK 现场编译**到 `.server-classes/`；
3. 都没有 → 回落到内核内置类。

所以：**改游戏服务端 = 改自己目录里的 `.java`，然后重新拨一下开关**
（停 → 开 会重新编译加载）。不用碰内核、不用重编 jar、不用重启服务器。

⚠️ 现场编译需要 **JDK**（有 `javac`）。只装了 JRE 时改用 `server.jar`。

## 五、导入 · 启停 · 删除

### 导入
启动器「＋ 添加游戏」→ **选游戏文件夹本身**（含 `game.json` 的那一层，
**不要**双击进 `server/`）→ 导入。

- `game.json` 本体不上传（服务端按新 id 重写）
- 其余文件（含 `server/` 整个子目录）全部上传
- 上限：单文件 ≤ 32MB、总量 ≤ 512MB、文件数 ≤ 2000
- 选错文件夹（既没 `game.json` 也没网页）会被直接拦下

### 启停
`game.json` 有 `world` 的游戏由**房主**在启动器里拨开关（上=开 / 下=关）。
同时运行上限 **4** 个；**里面还有玩家时停不掉**。

### 删除
每个游戏左上角 **✕**（房主专属）→ 确认 → 整个目录删掉，**不可恢复**。
游戏正在运行会先停掉；还有玩家时拒绝（等他们退）。

## 六、硬性红线（违反了必炸）

1. **客户端不能写死 `/api/<名字>`** → 必须从 `location.pathname` 取 id
2. **服务端类必须 `package lkserver;`**，否则内核工具用不了
3. **`join` 必须返回带 `id` 的 JSON**，否则客户端进不去
4. **别把 `server/` 当游戏文件夹导入**（那只是子目录，导进去只有源码、没有网页）
5. **导入后的游戏 id 是 `g<时间戳>`**，任何跨文件硬编码 id 都会失效

## 七、已知坑（都踩过）

| 坑 | 现象 | 解法 |
|---|---|---|
| `arcTo` 控制点重合 | 圆角矩形 `fill()` 只填出一点点，看着像"透明/缺口" | 四个控制点两两不同；`r` 夹到 `min(r, w/2, h/2)` |
| 每帧 `shadowBlur` | 低端机掉帧、卡顿 | 离屏 sprite 缓存 + `drawImage` |
| 假设同步间隔固定 | 画面一顿一顿（每次都等下一个快照） | 服务端下发步进相位，客户端按时间外推 |
| 改 `autostart` 没重启 | 自启状态和预期不符 | `autostart` 只在服务器启动时读一次 |
| 改静态文件后没生效 | 看到的是旧版 | 浏览器 Ctrl+F5（服务器每请求读盘，无需重启） |
| 客户端各自算规则 | 两边判定不一致 / 有人作弊 | **服务端权威**：所有判定在服务端，客户端只上报意图 |
| 名字直接塞进 innerHTML | XSS / 排版被破坏 | 服务端清洗 + 前端转义 |
| 玩家离线不清理 | 永远占位、房间满了进不去 | 做 IDLE（标离线）+ TIMEOUT（移除）两层 |
| 内核删了 `.java` 但 `out/` 有残留 | jar 里还带着已经删掉的类 | `build.bat` 每次 `rmdir out` 全量重编；手动编译时先清 `out/` |

- [ ] 联机：`join` 返回含 `id` 的 JSON

### 自测脚本怎么写

照 `test-gomoku.js` / `test-snake2.js`：直接打 HTTP 接口，不依赖浏览器。

```js
const BASE = 'http://127.0.0.1:8080';
const r = await fetch(BASE + '/api/mygame/join', { method: 'POST', /* ... */ });
```

联机世界默认不开，测试开头记得先 `POST /api/games/<id>/start`。

## 十、做新游戏的最短路径

1. 复制 `gamemode/snake/`（纯单机）或某个联机游戏做底子
2. 改 `game.json` 的 `id` / `name` / `desc` / `icon`
3. 写玩法，跑通「点开就能玩」
4. 要联机 → 加 `server/YourWorld.java`（照 `GomokuWorld` 抄结构），
   `game.json` 补 `"world": "lkserver.YourWorld"`
5. 写 `test-你的游戏.js`，把关键规则都断言一遍
6. 用启动器「＋ 添加游戏」导入一次，确认开关能开、能玩
