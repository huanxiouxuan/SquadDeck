# 已知坑（症状 → 根因 → 解法）

先看这张速查表，需要细节再看下面几条详述。

| 症状 | 根因 | 解法 |
|---|---|---|
| 导入后点进去是"这个游戏还没开工"的占位页 | 选文件夹时进了 `server/` 子目录（只有源码、没网页） | 重导，选**含 `game.json` 的那一层** |
| 导入后所有接口 404 | 客户端写死了 `/api/xxx` | 从 `location.pathname` 取 id |
| 拨开关报"加载世界失败"，接口一直 409 | `game.json` 的 `world` 类名错 / 源码没 `package lkserver;` | 核对类全名；看服务器日志 |
| `join` 成功了但进不去 | 返回的 JSON 里没有 `id` | `{"id":"p1",...}` 必须带 id |
| 画面"一格一跳"或"一顿一顿" | 直接画离散快照 / 假设快照间隔固定 | 服务端给步进相位，客户端连续外推 |
| 物体会"抖一下再追上来" | 每次快照都硬锚到服务端位置 | 连续性优先，只做**温和**漂移校正 |
| 圆角矩形几乎填不出面积（看着像透明） | `arcTo` 的两个控制点重合，路径退化成直线 | 四段标准写法，控制点两两不同 |
| 低端机卡顿 | 每帧 `shadowBlur` | 离屏 sprite 缓存 + `drawImage` |
| 改了 `autostart` 不生效 | 只在服务器**启动时**读一次 | 改完重启服务器 |
| 改了前端没反应 | 浏览器缓存 | Ctrl+F5 |
| 改了服务端没生效 | 世界还在跑，没重新加载 | 启动器上 stop→start（会重编） |
| 偶发 `ConcurrentModificationException` | tick 线程和 HTTP 线程没加锁 | 所有对外方法 `synchronized` |
| 房间/座位永远被占 | 离线玩家没清理 | IDLE 标离线 + TIMEOUT 移除 |
| 名字把布局撑坏 / 注入 HTML | 直接塞 `innerHTML` | 服务端清洗 + 前端 `esc()` |
| 本地跑得好好的，导入后全挂 | id / API 前缀写死；或依赖了绝对路径 | 一切路径从 `location` / 相对路径推 |

## 1. `arcTo` 控制点重合 —— "看着像透明"

```js
// ✗ 错的：P1 == P2，按 canvas 规范 arcTo 退化成直线
ctx.arcTo(x + w, y + h, x + w, y + h, r);
ctx.arcTo(x + w, y,     x + w, y,     r);
```

后果：路径自重叠、净环绕数为 0，`fill()` **几乎填不出面积**。
实测同尺寸（29×29, r=7）着色像素：**旧实现 14px / 正确实现 828px**。
看起来就是"蛇身/方块透明、只剩几个小楔形"。

```js
// ✓ 对的：四个控制点两两不同，r 夹到半边长
function roundRect(x, y, w, h, r) {
  var rr = Math.min(r, w / 2, h / 2);
  ctx.beginPath();
  ctx.moveTo(x + rr, y);
  ctx.arcTo(x + w, y,     x + w, y + h, rr);
  ctx.arcTo(x + w, y + h, x,     y + h, rr);
  ctx.arcTo(x,     y + h, x,     y,     rr);
  ctx.arcTo(x,     y,     x + w, y,     rr);
  ctx.closePath();
}
```

> 教训：**"看着像透明/缺口"不一定是几何算错，可能是光栅化塌了。**
> 几何断言全绿也测不出来 —— 测试里要检查**路径参数**，或者直接截图看像素。

## 2. 每帧 `shadowBlur` 会掉帧

`shadowBlur` 是模糊，等价于每帧做一次高斯卷积；软渲染 / 集显上非常贵。
食物光晕、发光文字这类静态效果，**预渲染到离屏 canvas**，之后只 `drawImage`：

```js
function makeGlowDisc(color, glow, size) {
  var c = document.createElement('canvas');
  c.width = c.height = size * 3;
  var g = c.getContext('2d');
  g.shadowColor = glow; g.shadowBlur = size;        // 只在这里做一次
  g.fillStyle = color;
  g.beginPath();
  g.arc(size * 1.5, size * 1.5, size, 0, Math.PI * 2);
  g.fill();
  return c;
}
```

## 3. 同步与插值：别假设"快照间隔固定"

**症状**：明明帧率 60，物体却一卡一卡的。

**根因**：客户端按 `(now - 上次快照) / 固定间隔` 算进度。但实际间隔是
"定时器 + 网络 + 服务端处理"的抖动值，每到一次快照就"卡住等下一个"。

**正确做法**（服务端权威游戏）：

1. 服务端在快照里给出**步进相位**：`sf = (now - 上次走步时刻) * 1000 / 步进毫秒`
   （用**精确的走步时刻**，不要用按 tick 量化过的累加器）
2. 客户端按时间**连续外推**：`相位 = 锚点相位 + (now - 快照到达) / 步进毫秒`
3. 新快照到达时，**把锚点相位调整到"绝对渲染位置不变"**（相位减 1 而不是跳变），
   再做极小的漂移校正（权重 0.15 左右），**不要硬锚**
4. 允许相位短暂 `> 1`（外推），设一个上限防止丢包时窜出去

验证手段：无头浸泡测试 —— 桩掉 canvas，用虚拟服务端驱动 3~5 秒，
逐帧采样物体位置，统计**冻帧率**和**帧间最大位移**。
指标参考：冻帧 < 1%、最大帧间位移 < 1 格。

## 4. 渲染"尾巴瞬移"

如果一条多节物体（蛇）第一次出现时只记录了头的位置，后面几节的历史就接不上，
第一次渲染会把整条身子"啪"地展开好几格。

解法：**首次创建渲染状态时，就把服务端给的完整身体一起存进去**，
不要只存头。

## 5. 导入后是占位页

这是我踩过的最容易被误解的一个：

- 导入时在文件夹选择框里**双击进了 `server/`**（那里只有服务端源码）
- 结果：只有源码被传上去，没有 `index.html` / `game.js`
- 服务端发现"清单里没有入口页" → 补一个**占位页**
- 同时没读到 `game.json` → `world` 字段丢失 → 被当成纯静态游戏（**连开关都没有**）

判断：看 `gamemode/<新id>/` 里有没有 `index.html`、`game.json` 里有没有 `world`。

正确操作：**选游戏文件夹本身**（含 `game.json` 的那一层）。
启动器现在会在"既没 game.json 又没 .html"时直接拦下。

## 6. 服务端 `sync` 抛异常 = 客户端"永久卡住"

客户端的同步循环通常是 `success → 排下一次`。
如果服务端在 `sync` 里抛了异常（返回 500，客户端 `.json()` 可能解析失败），
链条就断了，表现为"游戏不动了"，而且**没有任何报错提示**。

规矩：
- `sync`/`join` 内部**捕获所有可预期的异常**，返回兜底 JSON
- 客户端对 `.catch` 要计数 + 重连，不要静默停住

## 7. 测试自身的假故障

写自测时注意几个常见的"测试骗人"：

- **时序类断言会被 CPU 峰值打出假失败**（比如现场编译 Java 时），
  单独重跑一次再判断
- **桩 canvas 不真正光栅化**，`arcTo() {}` 这种"吞参数"的桩会让光栅化 bug 隐形
- **等待窗口要按最坏情况算**：地图放大了、移动变慢了，旧的等待秒数就不够了
- 桩服务端要模拟真实规则（例如撞墙是死亡，不能"退回来继续走"），
  否则测出来的是桩的 bug
