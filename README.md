# SquadDeck · 开黑启动器（lkserver2-game）

基于 [`lkserver2`](https://github.com/lk23276/lkserver2)（原项目为 C++ / Linux 实现）的 Java NIO 服务器内核，**扩展出来的一个多人联机小游戏启动器**。

玩法模型就一句话：**一个人在自己电脑上开服务器当"房主"，其他人用浏览器连进来，在左侧游戏栏挑个游戏一起开黑。**

启动器本身不带玩法——它负责三件事：**左侧游戏列表**（读 `gamemode/` 里各游戏的 `game.json`）、把选中的游戏**装进右侧窗口**（iframe）、以及**「添加游戏」**（从任意磁盘选文件夹，整份复制进 `gamemode/`）。
目前已收录三个游戏：**坦克世界**（服务端权威 30Hz 的多人坦克对战）、**贪吃蛇**（纯客户端单机经典玩法）和 **贪吃蛇联机版**（服务端权威的多人同屏贪吃蛇，`/api/snake2`）——它们的玩法、接口、自测等全部文档在各自目录里的 `README.md`（坦克在 `gamemode/tank/README.md`）。

内核没变——主从 Reactor、事件驱动、零拷贝、优雅关闭、完整 HTTP 解析都还在；所有玩法判定都在**服务端**完成，客户端只负责"上报按键/瞄准/开火"和"把世界画出来"。

## 一、怎么玩（最快路径）

**房主：双击桌面上的 `SquadDeck` 快捷方式**（或双击项目里的 `SquadDeck.bat`）。

它会自动完成：编译（首次）→ 启动服务器 → 打开浏览器进入**启动器页面**。

> 快捷方式是我帮你在桌面创建的：目标指向 `D:\项目\lkserver2-game\SquadDeck.bat`，图标取项目根目录的 `OIP-C.ico`（**启动器自己的图标**，与游戏图标相互独立）。
> 如果浏览器没自动弹出，手动访问 **<http://127.0.0.1:8080/>** 即可。

**进页面后**：左边是游戏栏，点一下想玩的游戏（目前是 **坦克世界**、**贪吃蛇**、**贪吃蛇联机版**），右边窗口立刻载入——坦克点**「开始」**直接进（名字在右上角「名字登记」栏设置，≤10 字），贪吃蛇选个难度直接开始，联机版输入昵称加入后所有人同屏竞技。

**其他玩家：** 在你自己电脑的浏览器里打开 **<http://127.0.0.1:8080/api/net>**——`addrs` 里列出的就是**实时**的可分享地址（每次请求现场枚举网卡，IP 变了刷新一下就是最新值），把合适的 `url` 发给朋友：

```json
{"port":8080,"addrs":[
  {"label":"MediaTek Wi-Fi 7 MT7925 Wireless LAN Card","ip":"10.16.145.109","url":"http://10.16.145.109:8080/"},
  {"label":"Famatech Radmin VPN Ethernet Adapter","ip":"26.242.181.68","url":"http://26.242.181.68:8080/"}
]}
```

> 挑选规则：同一个 Wi-Fi / 路由器 → 用 Wi-Fi 或以太网那条；不在同一网络 → 用 Radmin VPN 那条。
> 服务器启动横幅**不再打印地址列表**（启动时的一份快照会过期，不如不给）；要看实时地址就以 `/api/net` 为准。

> ⚠️ **千万别把 `http://127.0.0.1:8080/` 发给别人**——`127.0.0.1` 是"本机自己"，在别人电脑上打开等于连他自己，必然失败。
> 两台电脑不在同一网络时，用 **Radmin VPN**（双方加入同一网络）最省事。
> 还没装 Radmin VPN？双击项目里的 `下载VPN.bat`——自动从官网下载安装包到项目 `radmin-vpn\` 目录（安装需要管理员权限，因为要装虚拟网卡）。整个项目文件夹可以直接拷给朋友，朋友在自己电脑上运行 `radmin-vpn\radmin_vpn_free.exe`、加入**同一个** Radmin 网络即可联机。
> 详细说明见项目里的 `连接地址怎么填.txt`。

**用「热点」连**（没有路由器、没有网线时最省事）——分两种情况，填的地址不一样：

| 情况 | 别人该输入的网址 |
|------|------------------|
| **你这台电脑开热点**（Windows 设置 → 网络和 Internet → 移动热点 → 打开），别人连你的热点 | **`http://192.168.137.1:8080/`**（Windows 移动热点固定地址，照抄即可） |
| **大家都连同一个手机热点**（比如手机开热点，你和朋友都连上） | 填**你这台电脑连上热点后拿到的地址**：`ipconfig` 看"无线局域网适配器 WLAN"那栏的 IPv4（安卓热点常见 `192.168.43.x`、iPhone 热点常见 `172.20.10.x`），例如 `http://172.20.10.2:8080/` |

> 热点地址会出现在 <http://127.0.0.1:8080/api/net> 的实时列表里（网卡名带 "Wi-Fi Direct" 或 "本地连接*" 的那条，通常是 `192.168.137.1`）——**哪个是热点网段的就用哪个**。
> 第一次别人连不上，多半是防火墙（见下）。另外部分安卓手机热点默认隔离设备间互访，若 `ping` 通却打不开网页，优先改用"电脑自己开热点"或 Radmin VPN。

打不开的话，通常是 Windows 防火墙拦了 Java，在弹出"是否允许访问网络"时选**允许**即可（或运行项目里的 `开放防火墙8080.bat`，右键以管理员身份运行）。

### 怎么关掉服务器

服务器就是那个**专门开出来、标题写着 `SquadDeck Game Server` 的黑窗口**里跑的 `java.exe`。想关掉，任选一种：

| 方法 | 怎么做 | 说明 |
|------|--------|------|
| **① 关窗口（最直观）** | 直接点那个黑窗口右上角的 **×**，或在窗口里按 <kbd>Ctrl</kbd>+<kbd>C</kbd> | 关掉窗口 = 服务器停止 |
| **② 双击 `关闭服务器.bat`** | 双击项目里的 `关闭服务器.bat`（**不需要管理员**） | 它会自动找出占用 `8080` 的进程并结束，适合找不到窗口时 |
| **③ 任务管理器** | <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Esc</kbd> → 找到 `java.exe` → 结束任务 | 兜底手段 |

> **关掉之后**：别人/你自己打开游戏页都会连不上（连接被拒绝），这是正常的——服务器没了。
> **想再开**：重新双击桌面 `SquadDeck` 快捷方式（或 `SquadDeck.bat`）即可，游戏世界会**重新随机生成一张地图**，之前的对局不保留。

> 排查"到底关没关干净"：命令行执行 `netstat -ano | findstr :8080`，**没有任何输出**就说明已经关干净了（还显示 `LISTENING` 就说明还在跑）。

### 启动器与多游戏（gamemode 目录）

启动器页面（`www/index.html` + `www/launcher.js`）就干三件事：**列游戏、装游戏、加游戏**。

```
lkserver2-game/
├── www/                  ← 启动器本身（左侧游戏栏 + iframe + 添加游戏弹框）
│   ├── index.html
│   └── launcher.js
└── gamemode/             ← 一个小游戏一个目录（每个游戏自带前端 + 可选服务端）
    ├── tank/             ← 坦克世界（联机，自带服务端）
    │   ├── game.json     ← 游戏元数据
    │   ├── index.html    ← 入口页（/games/tank/ 打开的就是它）
    │   ├── game.js
    │   ├── sfx/
    │   └── server/       ← 自带服务端：GameWorld.java（内核自动编译加载）
    ├── snake2/           ← 贪吃蛇联机版（联机，自带服务端）
    │   ├── game.json / index.html / game.js
    │   └── server/       ← SnakeWorld.java
    ├── snake/            ← 贪吃蛇（纯客户端单机，没有服务端）
    │   └── game.json / index.html / game.js
    └── <你的新游戏>/      ← 「添加游戏」导入 or 自己手工建（server/ 会一起带上）
```

**`game.json` 字段**（每个游戏必须有一个，缺了就当这个目录不存在）：

| 字段 | 含义 |
|------|------|
| `id` | 目录名 / URL 片段，只能 `[a-z0-9_-]`；同时决定默认接口前缀 `/api/<id>` |
| `name` | 显示名（左侧列表、标题栏） |
| `desc` | 一句话简介（列表副标题） |
| `icon` | emoji，或游戏目录里的图片文件名（如 `tank.ico`，启动器列表渲染成图标图）；缺省 🎮 |
| `entry` | 入口文件名，缺省 `index.html` |
| `api` | 这个游戏用的服务端接口前缀，例如 `/api/tank` |
| `world` | （联机游戏才需要）服务端「游戏世界」类的全限定名，如 `lkserver.GomokuWorld`；类可以放在游戏目录的 `server/`（源码或 jar，内核自动编译加载）里——**这是推荐做法**；启动器据此在按钮上放启停开关 |
| `autostart` | （联机游戏才需要）`true` = 服务器启动时自动拉起这个世界（**坦克世界**就是）；缺省 = 等房主在启动器里拨开关 |
| `version` | 版本号，随意 |

**访问路径**：游戏网页文件通过 `/games/<id>/<文件>` 发出（`TcpConnection` 路由到 `gamemode/<id>/`，带目录穿越校验）；启动器 iframe 的 src 就是 `/games/<id>/`，省略文件名时发 `entry` 指向的入口页。

**添加游戏**（左侧栏底部「＋ 添加游戏」）——从任意磁盘选文件夹，整份复制进 `gamemode/`：

1. 点「＋ 添加游戏」→ 点**选择游戏文件夹**，在系统文件框里选（D 盘 / E 盘 / U 盘都行，选文件夹本身）；
2. 启动器读取内容：有 `game.json` 就用它的名称/简介/图标/入口页/接口前缀（自动预填，可改）；没有就按文件夹名生成，并给出黄色警告；
3. 点**导入** → 服务端先在 `gamemode/` 建好目录、按**全新 id** 写好 `game.json`（重复导入同一文件夹会得到不同副本，不会撞车），再逐个上传文件，弹框显示进度条；
4. 导完自动切到新游戏。清单里没有入口页时，服务端会补一个占位页，点进去能看到"文件该放哪、怎么声明接口"的说明。

> 上限：单文件 ≤ **32MB**、一次导入总量 ≤ **512MB**、文件数 ≤ **2000**（超限会被服务端拒绝并说明原因）。
> 上传中断（断网 / 关了页面）时，已传的文件留在 `gamemode/<id>/` 里——重试一次，或到资源管理器删掉那个目录再导。
> import / upload 会写文件，所以别把端口暴露给公网——设计目标是"房主本机 / 局域网自己用"。
> 手动增删游戏文件夹后，点左侧栏标题旁的 **⟳**（或刷新页面）会重新扫描 `gamemode/` 目录，不必重启服务器。

**删除游戏**——每个游戏按钮**左上角有个小叉 ✕**（平时淡淡的，鼠标移到该游戏上才明显）：

1. 点 ✕ → 弹确认框 → 确认后服务端把这个游戏的 `gamemode/<id>/` **整个目录删掉**
   （含网页、素材、`server/` 里的服务端源码），**不可恢复**；
2. **只有房主**（开服务器那台电脑）能删；好友点会被拒绝并提示（服务端同样 403）；
3. 游戏**正在运行**时会先把它停掉再删；**里面还有玩家**时拒绝删除（409，
   免得把朋友连人带局一起抹掉）——等他们退干净再删；
4. 删掉的正好是当前打开的游戏时，右侧会自动切到列表里的第一个游戏。

**名字登记**（启动器**右上角**）：一个 ≤10 字的输入框，填一次本地记住。进游戏**不用再输入名字**——点游戏里的「开始」直接进，用的就是这里登记的名字（启动器通过 `postMessage` 下发给 iframe 里的游戏）；服务端同样按 10 字截断兜底。**没登记名字时一切身份功能全部停用**（见下）。

**表情栏 + 聊天**（游戏窗口正下方、一样宽的通栏，**启动器自己的功能，与游戏完全无关**）：**左边是动态栏**（自己 + 服务器里所有人的消息和表情，带名字，自己的高亮），**右边是表情选择区 + 聊天输入框**（≤120 字，回车或点 ➤ 发送）。点一个表情：按钮缩一下、右侧显示"已发送 ♻"、动态栏追加一条自己的记录；打字发送同理。两边都走内核的 **`/api/chat` 公共频道**（全服一个房间）：发一条 → 服务器存一份并分配自增 id → 每个人每 1.5 秒增量轮询一次，新消息渲染进各自的动态栏。**不经过任何游戏的协议**——游戏接不接、运不运行都不影响；切游戏、甚至不选游戏，记录都接着算。消息只在内存里（最近 60 条 / 10 分钟），重启清空。

- 动态栏**固定高约 4 条（116px）**，再多就在栏内滚动——不会向上撑高底栏、挤压游戏窗口；**往上滑可以翻更早的记录**（DOM 里保留最近 30 条）。本来停在底部时新消息自动滚底；往上翻看历史时新消息不拽人
- 整个底栏压到约两行表情按钮高（12 个表情 6 个/行两行排完，按钮 30px）；游戏窗口相应拿回高度

- 表情库在 `www/launcher.js` 顶部的 **`EMOJI_LIST`**，一行数组，增删随意
- **无名字门禁（三层）**：没登记名字时——① 启动器 UI：聊天输入框/发送按钮/12 个表情按钮全部禁用（placeholder 变引导语），点游戏卡片也被拦（名字框红框抖两下 + toast 提示）；② 游戏客户端：加入时不再有随机名/本地存储兜底，直接提示去登记；③ 服务端：`join` 收到空名一律返回 `{"err":"请先在启动器右上角「名字登记」里填个名字（≤10 字）"}`，`/api/chat` 空名 400。登记后即时恢复，无需刷新
- 服务器只按长度截断（名字 ≤10 字、消息 ≤120 字），**不做字符过滤**：这是启动器的聊天室，不是游戏的输入协议；纯表情串在动态栏里大号显示，文字按文本样式显示
- 消息里的名字取右上角「名字登记」栏的值（进游戏点「开始」也是用这个名字，但那是另一条 `postMessage` 通道，与本功能无关）
- 焦点管理：点表情/聊天相关按钮不会把键盘焦点从游戏里抢走（详见「焦点管理」一节）；在聊天框里打字时焦点本来就在输入框，想用键盘玩游戏就点一下游戏画面

**无头端到端验证**（`测试文件/test-chat-e2e.js`，**17 项断言全绿**）：起两个 Edge 无头实例（CDP 9222/9223，真实鼠标点击 + 真实按键），实例 A 进五子棋创建房间、实例 B 进贪吃蛇联机版，两人分处不同游戏——① B 点启动器表情按钮后 `document.activeElement` 仍是游戏 iframe、iframe 键盘探针继续收到 w/d（焦点没被抢）；② B 发文字/表情，A 的底栏 1.5 秒内收到，A 发 B 也收到（跨游戏共通）；③ 五子棋 iframe 里没有任何聊天/表情 DOM、页面不显示聊天内容，旧协议 `postMessage({kaihei:'emoji'})` 双方均无反应且游戏不坏（协议已彻底拆除）；④ B 输房间码加入 A 的五子棋对局，同房期间聊天继续共通，双方动态栏条数一致。

**游戏启停开关**（左侧每个游戏按钮右侧）：上下滑动，**上=开、下=关**；只有联机游戏（有服务端世界的）才有，且只有房主（开服务器那台电脑）拨得动——好友看到锁定态。详见「二、游戏接口」里的「游戏启停开关（房主）」一节。

## 二、游戏接口（服务端权威）

前端调用下面这些 JSON 接口。**每个游戏的接口都挂在 `/api/<游戏id>/` 下**（与 `game.json` 的 `"api"` 字段对应），启动器级别的接口挂在 `/api/` 根下：

| 方法 | 路径 | 参数 | 作用 |
|------|------|------|------|
| `GET`  | `/api/games` | — | 启动器：全部小游戏列表（每次先重扫 `gamemode/` 目录；每个游戏带 `srv`=有没有服务端世界、`run`=是否在跑，顶层 `host`=你是不是房主） |
| `POST` | `/api/games` | `name`, `desc` | 启动器：创建空壳游戏（建目录 + 写 `game.json` + 占位页；供脚本用，界面导入已不走这里） |
| `POST` | `/api/games/import` | JSON：`name`, `desc`, `icon`, `entry`, `api`, `world`, `autostart`, `files[{p,s}]` | 启动器：导入第一步——建目录、按新 id 写 `game.json`（文件清单在这里事前校验：穿越/超限/重复全拦） |
| `POST` | `/api/games/upload` | 查询串 `game`, `path`；请求体 = 文件字节 | 启动器：导入第二步——把每个文件写进游戏目录（`application/octet-stream`，带目录穿越双保险） |
| `POST` | `/api/games/<id>/start` | — | **房主专属**：启动一个游戏世界（受同时启动上限约束，见下） |
| `POST` | `/api/games/<id>/stop` | — | **房主专属**：停掉一个游戏世界（里面还有玩家时拒绝） |
| `POST` | `/api/games/<id>/delete` | — | **房主专属**：删除一个游戏——先停它的世界（里面还有玩家时拒绝），再删掉 `gamemode/<id>/` 整个目录（**不可恢复**） |
| `POST` | `/api/<游戏id>/join` | `name`, `cid` | 联机游戏：加入，返回玩家 id 与世界参数；带 `cid` 同身份重连复用旧号；世界没启动返回 409 |
| `POST` | `/api/<游戏id>/sync` | `id` + 各游戏自定义输入 | 联机游戏：上报输入**并**取回世界快照（一次往返；输入参数由各游戏自己定义） |
| `POST` | `/api/<游戏id>/leave` | `id` | 联机游戏：主动退出 |
| `GET`  | `/api/<游戏id>/info` | — | 联机游戏：在线人数、地图尺寸等 |
| `GET`  | `/api/chat` | `after` | **启动器公共频道**（与游戏无关）：拉取聊天/表情消息——`after` 之后的增量，缺省回看最近 20 条 |
| `POST` | `/api/chat` | JSON：`name`, `text` | **启动器公共频道**：发一条消息（名字 ≤10 字、文本 ≤120 字，空白压缩），返回分配的 id |
| `GET`  | `/api/net` | — | **实时**枚举本机可分享的 IPv4 地址（要发给别人的联机地址就看这里，浏览器直接打开即可） |

> 联机游戏的 `join|sync|leave|info` 是**通用路由**（见上表）：`GameApi` 按游戏 id 去 `WorldRegistry` 找世界实例，不认识 id → 404、世界没启动 → 409。输入参数含义、世界快照字段、服务端 tick 逻辑各游戏不同——见对应游戏目录里的 README（坦克在 `gamemode/tank/README.md`；贪吃蛇联机版的规则写在 `gamemode/snake2/server/SnakeWorld.java` 的类注释里）。

> `/api/net` 会枚举本机所有「已启用、非回环、非链路本地」的 IPv4 地址
> （例如以太网 `10.x`、Radmin VPN `26.x`、Wi-Fi 网卡），并带上端口拼成完整 URL。
> **每次请求都现场枚举**——重连 Wi-Fi、VPN 换地址后，刷新一下拿到的就是最新值，
> 不存在"横幅还是旧 IP"的问题（服务器启动横幅因此不再打印地址列表）。
> 「移动热点」网卡（`Microsoft Wi-Fi Direct Virtual Adapter`，地址通常是 `192.168.137.1`）
> 在 Java 眼里算虚拟网卡，会被特别放行——否则开热点后反而看不到该用的地址。
> 完整说明见 `连接地址怎么填.txt`。

### 游戏启停开关（房主）

启动器左侧**每个游戏按钮右侧有一个上下滑动开关**：**上是开**（绿色、滑块在上），**下是关**（灰色、滑块在下）。只有**联机游戏**（`game.json` 里声明了 `world` 的游戏）才有开关；纯静态游戏（如单机贪吃蛇）没有服务端世界，随点随玩。

- **谁能拨**：只有房主——开服务器那台电脑（用 `127.0.0.1` 或自己的局域网/热点地址打开启动器都算）。好友从别的电脑连进来看到的是半透明锁定态，点拨会抖动并提示"只有房主可以启停游戏"（服务端同样以 403 拒绝）。
- **默认状态**：`game.json` 里 `"autostart": true` 的世界随服务器启动（目前只有坦克世界）；其余默认关着，等房主拨上去。
- **为什么要开关**：每个运行中的世界常驻一个 30Hz tick 线程——没人玩也在空转。不玩的游戏关掉，服务器更安静。
- **同时启动上限**：默认 **4** 个（`WorldRegistry.MAX_RUNNING`，想改就改源码里这一个常量再重编）。超上限时拨开关会提示 "too many games running"。
- **关不掉的情况**：游戏里还有在线玩家时 `stop` 会被拒绝（409）——等他们退干净，或空闲 5 秒被标离线后再关。关掉后世界对象销毁，再开是一块**全新的地图**（等同重开一局）。
- **没启动就进游戏**：好友点一个"未启动"的游戏，页面能打开，`join` 返回 409——贪吃蛇联机版的客户端会**自动拉起世界再重试**（只有房主/本机能启动，朋友会拿到 403 并看到"让房主拨开关"的提示）；坦克世界则是 `autostart: true`，服务器开着就一直在跑

### 怎么添加一个联机游戏（游戏自带服务端代码）

**内核不认任何具体游戏**——每个联机游戏的世界类都放在**游戏自己的目录**里，
内核启动这个世界时自动编译 / 加载。所以要加（或从网上拿）一个联机游戏，
**完全不用碰内核、不用重编 jar、不用重启服务器**：

1. 在游戏目录里放服务端代码，二选一（也可都放）：
   - `server/` 下的 `*.java` **源码** —— 服务器用自带 JDK 现场编译（推荐：改完重拨一下开关即生效）；
   - `server.jar` —— 已经编译好的插件包（不想给源码时用）；
2. 世界类实现 `GameWorldPlugin` 接口（`start/stop/join/sync/leave/info/playerCount`，
   参数语义见接口注释）。**接口和 `Json` / `Emoticons` 这些工具都在内核里**，
   源码直接 `package lkserver;` 就能用，不必复制一份；
3. `game.json` 里写 `"world": "你的类全名"`（如 `"lkserver.GomokuWorld"`）；
   想随服务器自启就再加 `"autostart": true`；
4. 用启动器「＋ 添加游戏」把整个文件夹导进来（`server/` 会一起传上去）；
5. 房主在游戏按钮右侧拨开关启动；客户端照旧打 `/api/<id>/join|sync|leave|info`
   四个通用接口（同步参数由世界类自己解析，服务端不区分游戏）。

> 三个联机游戏**全都自带服务端**：坦克 `gamemode/tank/server/GameWorld.java`、
> 贪吃蛇联机版 `gamemode/snake2/server/SnakeWorld.java`、五子棋
> `gamemode/gmv9ny2bh/server/GomokuWorld.java`（房间制对局 + **人机对战**：
> `server/GomokuAI.java` 是 Negamax + Alpha-Beta 搜索，说明见同目录 `README.md`）。
> 内核 `src/lkserver/` 里没有任何一个具体游戏。

> ⚠️ 源码编译需要 **JDK**（有 `javac`）。只装了 JRE 时 `server/*.java` 编不了 ——
> 改用 `server.jar`，或换 JDK 运行服务器。
> ⚠️ 加载即执行：导入的游戏服务端代码会在本机跑。别把来路不明的游戏往公网服务器上装。

> 自测脚本照 `测试文件/test-gomoku.js` / `测试文件/test-snake2.js` 的写法写——注意联机世界默认不开，
> 测试开头要先 POST `/api/games/<id>/start`。
> 两条路径测试覆盖不到，需特定环境：非房主拨开关 → 403（要从另一台电脑连进来才能测）；同时启动上限 → 409（需要 5 个以上声明了 `world` 的游戏）。

## 四、快速开始（不用快捷方式时）

### 环境要求

只需要 **JDK 17 或更高版本**。无需任何第三方依赖、无需 Maven/Gradle。

`build.bat` / `run.bat` 会按下面的顺序**自动查找 JDK**，一般不用手动配：

1. 脚本顶部的 `JK_JDK_HOME`（手动指定，默认留空）
2. 环境变量 `JAVA_HOME`
3. `PATH` 里的 `javac` / `java`
4. 用户目录下的 `%USERPROFILE%\.jdks\*`（IntelliJ IDEA 等 IDE 下载的 JDK 都放这里）
5. 本机免安装 JDK 目录

如果全都找不到，脚本会提示你去 <https://adoptium.net/temurin/releases/> 下载安装。
想手动指定，把脚本开头的 `set "JK_JDK_HOME="` 改成你的 JDK 根目录即可（例如 `D:\Java\jdk-21`）。

> **换电脑 / 电脑上没装 JDK**：双击项目里的 `下载便携JDK.bat`——它会自动下载 Temurin 21 LTS（Windows x64 zip 版）并解压到项目 `jdk\` 目录，同时把 `build.bat` / `run.bat` 顶部的 `JK_JDK_HOME` 指向它（写字面量 `%~dp0jdk`，项目整体挪盘符/换路径也不会失效）。之后整个文件夹拷贝到任何 Windows 电脑都能直接跑，无需安装 JDK。

> **换电脑 / 朋友没装 Radmin VPN**：双击项目里的 `下载VPN.bat`——它会自动从 radmin-vpn.com 下载官方安装包（`radmin_vpn_free.exe`）到项目 `radmin-vpn\` 目录，下载后可选择立即安装。Radmin VPN 是跨网络联机用的免费虚拟局域网工具，安装需要管理员权限（要装虚拟网卡），装好双方加入**同一个** Radmin 网络即可联机。

> **说明**：装了 IntelliJ IDEA / PyCharm 的话，它们自带 JetBrains Runtime（`<IDE 安装目录>\jbr\`，含 `javac`），IDE 还会把下载的 JDK 放在 `%USERPROFILE%\.jdks\`。这些都能被脚本自动识别——**不需要单独再装 JDK**。

> **注意**：两个 `.bat` 文件的内容刻意保持**纯 ASCII**。因为 Windows 的 `cmd.exe` 是按系统 ANSI 代码页（简体中文系统为 GBK）解析批处理文件的，`.bat` 里写中文会导致字节错位、命令解析失败。服务端程序本身的中文日志不受影响——`run.bat` 里已用 `chcp 65001` + `-Dstdout.encoding=UTF-8` 让控制台按 UTF-8 正确显示中文。

### 编译

```bat
build.bat
```

它做三件事：**清空 `out\`** → `javac` 把 `src\lkserver\*.java` 编译进 `out\` → `jar` 把 `out\` 打包成 `lkserver2-game.jar`。

> 为什么要先清空 `out\`：`javac` 只会**往里加** `.class`，从不删除。若某天你删掉或重命名了源码里的类，旧 `.class` 会一直留在 `out\` 里、并被一起打进 jar（本项目就曾残留过一个贪吃蛇时代的 `GameWorld$Snake.class`）。每次全量重编译能保证 `out\` 与 `src\` 严格一致。

### 运行

```bat
run.bat 8080 www
```

参数说明：

| 参数 | 含义 |
|------|------|
| 第 1 个 | **端口号** |
| 第 2 个 | **启动器目录**（Web 根目录，放 `index.html` / `404.html`） |
| 第 3 个 | 可选，**子反应堆线程数**，默认 4 |
| 第 4 个 | 可选，**游戏目录**，默认 `<启动器目录>/../gamemode` |

打开浏览器访问 `http://127.0.0.1:8080/` 即可。

> 与原版一致：启动器目录下**必须有 `404.html`**，请求不存在的资源时会返回它。
> 游戏目录不存在也能启动——启动器会显示"游戏库是空的"，用「添加游戏」建第一个即可。

## 五、功能一览

在本项目（启动器版）里新增的能力：

- **多游戏启动器**：左侧游戏栏（图标/名称/简介）→ 点选后 iframe 载入 `/games/<id>/`；「＋ 添加游戏」从任意磁盘选文件夹整份导入（自动识别 `game.json`，32MB/文件、512MB/次上限）；**每个游戏左上角 ✕ 删除（房主专属，弹确认框、先停世界再删目录）**；`GET /api/games` 每次重扫 `gamemode/` 目录，手动增删文件夹后刷新即生效
- **表情栏 + 聊天（启动器组件，与游戏无关）**：游戏窗口下方通栏，左边动态栏（自己 + 服务器里所有人的消息和表情，带名字，留最新 30 条）+ 右边表情选择区与聊天输入框（≤120 字，回车发送）；全部走 `/api/chat` 公共频道（全服一个房间，1.5 秒增量轮询）——游戏接不接、运不运行都不影响，切游戏不清记录；表情库改 `www/launcher.js` 里的 `EMOJI_LIST` 一行；名字在右上角「名字登记」（≤10 字）
- **焦点管理**：点启动器上的按钮/列表不抢 iframe 里游戏的键盘焦点（mousedown 阶段 `preventDefault` + click 后把焦点还给 iframe）——玩着贪吃蛇点表情、拨开关、刷新列表，WASD 一直管用
- **静态首页**：请求目录时优先返回目录下的 `index.html`（否则访问 `http://ip:port/` 只会看到文件列表，别人就没法"打开地址就进游戏"）
- **局域网友好**：`/api/net` 实时枚举本机可被其他机器访问的地址，过滤掉回环与 `169.254` 链路本地地址

> 游戏侧的玩法特性（联机世界、可破坏地图、坦克/弹药/视野/警戒、事件音效、身份复用等）见游戏自己的 README——目前是 **`gamemode/tank/README.md`**。

服务器内核部分与原 C++ 版完全对齐：

- **HTTP 静态资源服务**：请求目录返回文件列表，请求文件返回内容，不存在返回 `404.html`
- **完整的 HTTP/1.x 请求解析**：请求行 + 请求头 + 请求体全部解析，能处理半包 / 粘包 / 流水线（详见第五节）
- **主从 Reactor 模型**：1 个主反应堆 `accept` 新连接，N 个子反应堆（默认 4）处理已连接 socket 的读写，轮询分发做负载均衡
- **零拷贝发送文件**：`FileChannel.transferTo` 直接把文件从内核送入 socket，不经用户态内存
- **写半包续发**：响应头 / 目录列表走输出缓冲，写不完时挂 `OP_WRITE` 续发，不自旋、不阻塞
- **URL 解码**：支持 `%XX` 形式的中文等非 ASCII 路径
- **MIME 类型识别**、**优雅关闭**（Ctrl+C 停 accept → stop 并 join 子反应堆 → 主反应堆退出）

额外补充的几处（原版的已知 TODO，顺手修掉了）：

| 改进点 | 说明 |
|--------|------|
| 目录穿越防护 | 解析后的路径强制校验必须仍在 Web 根目录内，`../../Windows/win.ini` 这类请求会被拒 |
| 接收缓冲可增长 | 原版固定 4096 字节，超长请求会被截断；这里按需翻倍扩展，上限为「头部上限 + 正文上限」 |
| **解析请求头与请求体** | 原版只从请求行取 method/url，请求头被整个丢弃；现在完整解析并保留（第五节） |
| **长连接语义正确** | 按 `Connection` 头与协议版本决定保持还是关闭：HTTP/1.1 默认保持、HTTP/1.0 默认关闭 |
| 目录 / 404 带正确的 `Content-Length` | 原版发 `Connection: close` 靠断开界定正文；这里长度可预知，直接给准确长度，支持 HTTP/1.1 长连接 |
| 多支持 `HEAD` 请求 | 只回响应头不发正文，便于压测与探测 |
| 零拷贝兜底路径 | 极端情况下 `transferTo` 不前进时自动退回「读一块、写一块」，保证一定能发完 |

## 六、HTTP 解析能力

原 C++ 版只从请求行里取走 method 与 url，**请求头被直接丢弃**。本轮补上了完整的 HTTP/1.x 解析，代码在 `HttpParser.java` 与 `HttpRequest.java`。

### 解析范围

| 部分 | 解析内容 |
|------|----------|
| 请求行 | 方法、请求目标、协议版本 |
| 请求目标 | 拆成「路径 + 查询串」；`%XX` 百分号解码；兼容代理常用的绝对形式 `http://host/path` |
| 请求头 | 全部存入 `Map`（键统一小写）；支持 `obs-fold` 续行、重名头合并 |
| 请求体 | 按 `Content-Length` 读全，挂在 `HttpRequest.body` |

### 两种"字节流"问题都处理了

- **半包**：一次读事件只收到半个请求 → 解析器记住进度，下次读事件接着解析
- **粘包 / 流水线**：一次收到两条完整请求 → `processBuffer()` 循环逐条取出、逐条响应

### 体积上限（防内存被打爆）

| 常量 | 值 | 超限响应 |
|------|-----|----------|
| `HttpParser.MAX_HEADER_SIZE` | 32 KiB | `431 Request Header Fields Too Large` |
| `HttpParser.MAX_BODY_SIZE` | 1 MiB | `413 Payload Too Large` |
| `HttpParser.MAX_HEADERS` | 128 个 | `431` |

> 需要更大的上传体积，改 `HttpParser.MAX_BODY_SIZE` 后重新编译即可。注意正文目前是**整体缓冲在内存里**的，真要支持大文件上传应改为流式落盘。

### 错误码

| 触发条件 | 状态码 |
|----------|--------|
| 请求行格式错误 / 请求头缺冒号 / `Content-Length` 非法 | `400 Bad Request` |
| 请求头超限、头数过多 | `431 Request Header Fields Too Large` |
| 请求体超过 `MAX_BODY_SIZE` | `413 Payload Too Large` |
| `Transfer-Encoding: chunked`（未实现） | `501 Not Implemented` |
| 非 `HTTP/1.0` / `HTTP/1.1` 版本 | `505 HTTP Version Not Supported` |
| 非 `GET` / `HEAD` 的方法 | `501 Not Implemented` |

> 关于 `Transfer-Encoding`：这里**明确拒绝**而不是"尽力猜长度"。长度歧义正是 HTTP 请求走私（request smuggling）漏洞的源头，拒绝比猜测安全。

### 连接语义

| 请求 | 行为 |
|------|------|
| `HTTP/1.1`（默认） | 保持长连接 |
| `HTTP/1.1` + `Connection: close` | 响应带 `Connection: close` 后关闭 |
| `HTTP/1.0`（默认） | 响应带 `Connection: close` 后关闭 |
| `HTTP/1.0` + `Connection: keep-alive` | 响应带 `Connection: keep-alive`，保持 |
| 带 `Expect: 100-continue` | 先回 `HTTP/1.1 100 Continue`，再收正文 |

另外，对端发 FIN（读到 EOF）时会**先把缓冲区里已收全的请求处理完**再关闭，避免"请求发完就 shutdown write"的客户端丢掉响应。

### 实测结果

18 组用例、30 条断言全部通过（半包、流水线、100-continue、各类错误码、HTTP/1.0/1.1 开关连接、绝对形式目标、中文路径、目录穿越拦截），零拷贝发送 60MB 文件 md5 校验一致。

## 七、与原 C++ 版的架构对应关系

这是本项目最值得对照阅读的部分——**同一个架构，在两种语言里的等价写法**：

| 原 C++ 实现 | Java 对应实现 | 说明 |
|-------------|---------------|------|
| `select` / `poll` / `epoll` + `Dispatcher` 接口 | `java.nio.channels.Selector` | Java 把三种多路复用统一抽象成 `Selector`，由 JDK 按平台选底层实现；**不再需要手写三套分发器** |
| `eventfd` 跨线程唤醒 | `Selector.wakeup()` | 语义一致：让阻塞在 select 上的反应堆立即醒来，消除固定超时轮询的延迟 |
| 跨线程直接注册 fd + 一把 `pthread_mutex` 保护 `channelMap` | 「投递任务 + wakeup」模型（`EventLoop.execute`） | Java 的 Selector 不允许在阻塞期间被注册/注销，因此所有注册都在反应堆线程内完成，**顺带免掉了那把锁和数据竞争** |
| `Channel`（fd + 事件 + 回调） | `SelectionKey` + `EventHandler` 接口 | 回调挂在 key 的 attachment 上 |
| `EventLoop` | `EventLoop` | 一一对应 |
| `EventLoopThread`（pthread + 条件变量） | `EventLoopThread`（`Thread` + `CountDownLatch`） | 等待「子反应堆创建完成」的方式不同，目的相同 |
| `EventLoopThreadPool` / `getNextLoop` | `EventLoopThreadPool` / `getNextLoop` | 轮询负载均衡，逻辑完全一致 |
| `Acceptor::acceptC` | `Acceptor.handleAccept` | accept 循环 + 轮询分发给子反应堆 |
| `TcpConnection` | `TcpConnection` | 读事件解析请求、写事件续发 |
| `sendfile(2)` 零拷贝 | `FileChannel.transferTo` | Windows 下底层是 `TransmitFile`，Linux 下是 `sendfile`，同样不进用户态内存 |
| `Buffer` + `EPOLLOUT` 写半包续发 | `outQueue`（ByteBuffer 队列）+ `OP_WRITE` | 机制完全对应 |
| `signalfd` 优雅关闭 | `Runtime.addShutdownHook` + `EventLoop.stop()` | Java 没有信号 fd，用关闭钩子达到等价效果 |
| `chdir(argv[2])` | `ServerContext` 保存根目录 + 路径校验 | Java 不能改进程工作目录，改用显式根路径，更安全 |
| `MSG_NOSIGNAL` 防 SIGPIPE | Java socket 不会产生 SIGPIPE | 平台已保证，无需处理 |
| `snprintf` / `sscanf` 宽度限定 | Java 字符串天然边界安全 | 无需处理 |

> 桌面快捷方式：`%USERPROFILE%\Desktop\SquadDeck.lnk` → 指向 `SquadDeck.bat`，图标取项目根目录的 `OIP-C.ico`（启动器图标，与游戏图标无关）。

> **文件归属原则**：单个游戏的所有文件（页面、脚本、图标、音效等素材）全部放在 `gamemode/<游戏id>/` 目录里；
> `www/` 和根目录下的脚本只服务于启动器本身，不放任何游戏资产——游戏与启动器相互独立，
> 增删游戏、换游戏图标都只在 `gamemode/` 里进行，不碰启动器。
> 启动器自己的资产（如快捷方式图标 `OIP-C.ico`）放根目录；游戏的资产（如坦克世界的 `tank.ico`）放游戏目录，两者互不引用。

## 九、已验证的功能

### 游戏部分

坦克世界的无头自测（`测试文件/test-game.js`，**30 项断言**：地图密度、连通性、转身、弹匣、视野、警戒、爆炸事件、身份复用、名字上限、导入链路等）的跑法与完整结果记录在 **`gamemode/tank/README.md`**。（原「⑨ 表情广播」一节已移除：表情和聊天是启动器自己的功能，走 `/api/chat`，与游戏协议无关。）

贪吃蛇两个版本的自测：

| 脚本 | 覆盖 | 结果 |
|------|------|------|
| `测试文件/test-snake2.js` | 联机规则（启停开关、身份复用、撞墙/撞人、尸体变果实、3 秒复活、非法输入），19 项 | 全绿 |
| `测试文件/test-snake-render.js` | 渲染链路（桩 DOM/canvas + 虚拟服务端驱动），28 项：冻帧、帧间位移、相机、头脖距、节间距、离路径、sprite 缓存、**arcTo 退化路径** | 全绿 |
| `测试文件/test-snake-latency.js` | 延迟矩阵 LAT 0/40/80ms × 步进 150/70ms，逐格独立子进程 | 6/6 达标 |

> **易踩的坑：桩 canvas 光栅化不了。** 「蛇身透明」真正的根因是圆角矩形的 `arcTo` 写法有缺陷——`arcTo(x1,y1,x2,y2,r)` 的**第一控制点与终点重合**时按规范退化成直线，路径变成自重叠路径、净环绕数为 0，`fill()` 几乎填不出面积（实测同尺寸只填出 **14** 个像素，正确应为 **799**），蛇身就渲染成一节节小碎片——看着像「透明」。
> 这类 bug 靠几何断言**永远测不出来**（几何完全正确，是光栅化塌了），必须在测试里检查**路径参数**：`测试文件/test-snake-render.js` 会跟踪 `moveTo/lineTo/arcTo` 的当前点，任何 `arcTo` 出现 `P0==P1` 或 `P1==P2` 即判 FAIL。两个蛇共用同一个 helper，所以一起修、一起防。

### 服务器内核部分

在 Windows + JDK 21 / 27 上实测通过：

| 测试项 | 结果 |
|--------|------|
| 首页 / 文件访问 | `200`，`Content-Length` 正确 |
| 目录列表 | 返回文件表格，含大小、`../` 上级链接、中文文件名百分号编码 |
| 404 | 走自定义 `404.html` |
| 中文文件名（`%XX` 解码） | 正常返回 |
| `HEAD` 请求 | 只回响应头 |
| 目录穿越（`../` 与 `%2f` 两种写法） | 均返回 `404` |
| 60MB 大文件下载 | 约 250–320MB/s，下载文件 md5 与源文件**完全一致**（验证零拷贝 + 续发无丢字节） |
| 12 路并发 | 全部 `200`，轮询分发到 `SubReactor-0/1/2/3` |
| 单连接连发 3 个请求 | 全部 `200`（长连接可用） |
| 优雅关闭 | 主反应堆退出，子反应堆线程全部回收（存活 0），进程正常退出 |
| **半包（请求分两次到达）** | 拼齐后正常响应 |
| **流水线（一次发两条请求）** | 两条响应都正确返回 |
| **POST 带正文 + 同连接后续 GET** | 正文被正确吞掉，后续请求不受污染 |
| **`Expect: 100-continue`** | 先回 `100 Continue`，再回业务响应 |
| **错误码 400 / 413 / 431 / 501 / 505** | 均按预期返回 |
| **HTTP/1.0 与 1.1 的连接开关语义** | 与 `Connection` 头一致，`Connection: close/keep-alive` 正确回写 |
